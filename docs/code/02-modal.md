# 2. Модальное окно

[shared/ui/modal.tsx](../../src/shared/ui/modal.tsx)

## Где на экране

«Новая операция», «Правка операции», «Новый бюджет», «Вернуть демо-данные?». Окно поверх
страницы, страница под ним затемнена и размыта.

## Что делает

- Открывается и закрывается по пропу `open`.
- Пока окно открыто, клавиша Tab ходит **только по окну**: на кнопки страницы под ним не попасть.
- Закрывается по Esc, по крестику и по клику на затемнение.
- После закрытия фокус возвращается на кнопку, которая окно открыла.
- Плавно появляется (снизу вверх и из прозрачности); на телефоне выезжает снизу как «шторка».

## Пропсы

| Проп | Тип | Зачем |
| --- | --- | --- |
| `open` | `boolean` | открыто ли окно |
| `onClose` | `() => void` | что сделать при закрытии (Esc, крестик, затемнение) |
| `title` | `string` | заголовок окна; его же прочитает скринридер |
| `children` | элементы | содержимое |
| `footer` | элементы | кнопки внизу (необязательно) |

## Как пользоваться

```tsx
function DeleteAll() {
  const [open, setOpen] = useState(false)
  return (
    <>
      <Button onClick={() => setOpen(true)}>Сбросить</Button>
      <Modal
        open={open}
        onClose={() => setOpen(false)}
        title="Вернуть демо-данные?"
        footer={<Button variant="danger" onClick={reset}>Сбросить</Button>}
      >
        <p>Ваши операции удалятся.</p>
      </Modal>
    </>
  )
}
```

Состояние «открыто или нет» хранит **родитель**. Окно только показывает его и сообщает
«меня закрывают» через `onClose`. Такой компонент называют **управляемым** (controlled).

## Почему `<dialog>`, а не `<div>`

Раньше модальные окна делали из `<div>` с `position: fixed` и писали вручную:

| Что нужно | На `<div>` | На `<dialog>` + `showModal()` |
| --- | --- | --- |
| окно поверх всего | `z-index: 9999` и надежда | верхний слой браузера (top layer), выше любого `z-index` |
| Tab не уходит на страницу | ловушка фокуса, ~60 строк | страница под окном становится `inert` сама |
| Esc закрывает | обработчик `keydown` | встроено |
| фокус возвращается | запомнить и вернуть вручную | встроено |
| скринридер понимает, что это окно | `role="dialog" aria-modal` | встроено |

Всё это мы получаем, вызвав один метод — `dialog.showModal()`.

## Код по частям

```tsx
export function Modal({ open, onClose, title, children, footer }: ModalProps) {
  const ref = useRef<HTMLDialogElement>(null)
  const titleId = useId()
```

- `useRef` — «ручка» к настоящему DOM-элементу `<dialog>`. Через неё вызываем
  `ref.current.showModal()`. Это метод элемента, а не проп, поэтому без ref его не вызвать.
- `useId` — уникальный id для заголовка (см. [Field](01-basics.md#field--подпись--поле--ошибка)).

```tsx
  useEffect(() => {
    const dialog = ref.current
    if (!dialog) return
    if (open && !dialog.open) {
      dialog.showModal()
      dialog.querySelector<HTMLElement>('[data-autofocus]')?.focus()
    }
    if (!open && dialog.open) dialog.close()
  }, [open])
```

Это **мост** между React и браузером. В React окно описывается состоянием (`open = true`),
а браузер хочет, чтобы вызвали метод (`showModal()`). Эффект запускается каждый раз, когда
меняется `open`, и приводит браузер в соответствие:

| `open` (React) | `dialog.open` (браузер) | Действие |
| --- | --- | --- |
| `true` | `false` | открыть: `showModal()` |
| `false` | `true` | закрыть: `close()` |
| совпадают | | ничего |

Проверки `!dialog.open` нужны, потому что вызвать `showModal()` у уже открытого окна — ошибка.

**Строка про `data-autofocus`** — история бага ([урок 2](../lessons.md)). `showModal()`
ставит фокус на первый фокусируемый элемент — крестик в шапке. А в форме операции хочется,
чтобы курсор сразу стоял в поле суммы. `autoFocus` из React не помогает: он срабатывает
**раньше** эффекта, и `showModal()` перебивает его. Поэтому после `showModal()` мы сами ищем
поле с пометкой `data-autofocus` и ставим фокус туда.

```tsx
  return (
    <dialog
      ref={ref}
      className={s.dialog}
      aria-labelledby={titleId}
      onClose={onClose}
```

- `aria-labelledby={titleId}` — «название окна — в элементе с этим id» (это `<h2>` ниже).
  Скринридер скажет: «Диалог: Новая операция».
- `onClose` — браузер шлёт событие `close`, когда окно закрылось **любым** способом, например по Esc.
  Мы пересылаем его родителю, и тот ставит `open = false`. Без этого была бы рассинхронизация:
  браузер окно закрыл, а React думает, что оно открыто, и повторно открыть его кнопкой не получится.

```tsx
      onClick={(event) => event.target === event.currentTarget && onClose()}
    >
```

Клик по затемнению. Хитрость в том, что затемнение (`::backdrop`) — часть самого `<dialog>`,
отдельного элемента нет. Поэтому:

- `event.currentTarget` — элемент с обработчиком, то есть `<dialog>`;
- `event.target` — элемент, по которому **на самом деле** кликнули.

Всё содержимое лежит во внутреннем `<div className={s.box}>`. Клик внутри окна — `target` это
`div` или кнопка, условие ложно. Клик мимо окна — `target` равен самому `<dialog>`, закрываем.

```tsx
      {open && (
        <div className={s.box}>
          <header className={s.header}>
            <h2 id={titleId} className={s.title}>{title}</h2>
            <button type="button" className={s.close} onClick={onClose} aria-label="Закрыть">
              <X />
            </button>
          </header>
          <div className={s.body}>{children}</div>
          {footer && <footer className={s.footer}>{footer}</footer>}
        </div>
      )}
    </dialog>
```

`{open && …}` — содержимое существует, только пока окно открыто. Закрыли окно — форма внутри
размонтировалась, и при следующем открытии она чистая, без старых значений и ошибок.

У крестика нет текста, только иконка, поэтому `aria-label="Закрыть"` даёт ему имя для скринридера.

## Анимация без JavaScript

[modal.module.scss](../../src/shared/ui/modal.module.scss):

```scss
.dialog {
  opacity: 0;
  translate: 0 12px;                         // закрытое: прозрачное и на 12px ниже
  transition: opacity 0.2s, translate 0.2s,
    overlay 0.2s allow-discrete, display 0.2s allow-discrete;

  &[open] {
    opacity: 1;
    translate: 0;                            // открытое: видимое и на месте

    @starting-style {                        // с чего начать, когда только появилось
      opacity: 0;
      translate: 0 12px;
    }
  }
}
```

Раньше анимировать появление было сложно: элемент появляется сразу (`display: none` →
`block`), и переходу не из чего начинать. `@starting-style` говорит браузеру: «в первый
момент считай, что стили были такими». `allow-discrete` для `display` и `overlay` даёт окну
доиграть анимацию закрытия, прежде чем исчезнуть.

На телефоне (`@media (width <= 600px)`) окно прижато к низу во всю ширину — как шторка в
мобильных приложениях, до кнопок легко дотянуться большим пальцем.

## Что будет, если…

- **убрать `onClose={onClose}` у `<dialog>`** — закройте окно по Esc и попробуйте открыть снова.
  Не откроется: React думает, что `open` всё ещё `true`, и эффект не запускается;
- **убрать `{open && …}`** — откройте форму, введите сумму, закройте, откройте снова: старая сумма
  и ошибки на месте;
- **вызвать `dialog.show()` вместо `showModal()`** — окно откроется, но Tab начнёт уходить на
  страницу, Esc перестанет работать, затемнения не будет.

## Проверьте себя

1. Почему `open` хранит родитель, а не сам `Modal`?
2. Откройте форму операции и нажимайте Tab много раз. Куда уходит фокус после последней кнопки?
3. Зачем проверка `event.target === event.currentTarget`?

<details>
<summary>Ответы</summary>

1. Открывать окно должен кто-то снаружи (кнопка, клавиша N), и знать, открыто ли оно, тоже нужно
   снаружи. Если бы состояние было внутри, родителю пришлось бы как-то «дотягиваться» в компонент.
2. По кругу внутри окна (и в адресную строку браузера), но не на страницу под окном: она `inert`.
3. Чтобы закрывать окно только по клику на затемнение, а не по любому клику внутри окна.
   Без проверки клик по полю суммы закрывал бы форму.
</details>
