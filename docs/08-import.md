# 08. Импорт выписки

[features/import-statement](../src/features/import-statement/) — мастер из четырёх шагов:
Файл → Колонки → Проверка → Готово.

## Разбор — чистые функции

[lib/parse.ts](../src/features/import-statement/lib/parse.ts) — без React и Redux: текст на
входе, строки на выходе. Поэтому легко тестируется ([parse.test.ts](../src/features/import-statement/lib/parse.test.ts)).

- **Кодировка.** Банки отдают UTF-8 или Windows-1251. Декодируем как UTF-8; если появился
  символ-заменитель U+FFFD (байты не сложились) — значит, 1251.
- **CSV.** Papa Parse угадывает разделитель (`;`, `,`, табуляция) и понимает кавычки:
  `"ООО ""Ромашка"", Москва"` — одна ячейка.
- **Заголовки.** Первая строка — заголовки, если в ней нет ни дат, ни сумм.
- **Колонки.** Сначала по заголовкам («Дата операции», «Сумма»), без них — по содержимому:
  где 80 % ячеек — даты, где суммы, а описание — самая «текстовая» колонка.
- **Даты.** «14.10.2026», «14/10/26», «2026-10-14 12:30». 31.02 отклоняется: `new Date`
  молча «перескочил» бы на 3 марта, поэтому проверяем, что день остался тем же.
- **Категории.** Правила по ключевым словам: «ПЯТЕРОЧКА 4512» → Продукты.
- **Ошибки — по строкам**, а не исключением: одна кривая строка не роняет весь файл.

## Состояние — слайс + селекторы

Черновик импорта — клиентское состояние (на сервере его ещё нет), поэтому `createSlice`.
В слайсе только исходные данные: таблица, разметка колонок, правки пользователя.
Строки, итоги и тела запросов — мемоизированные селекторы (глава 02). Сменили колонку —
строки пересчитались; правки категорий сбросились, потому что строки стали другими.

## Дубликаты

Повторный импорт той же выписки не должен задвоить операции. Сервер считает дубликатом
операцию с той же датой, суммой, типом, счётом и описанием и пропускает её:
«Добавлено: 0, пропущено как дубликаты: 14».
