# Шпаргалка к собеседованию

Вопросы, которые задают про Redux Toolkit, RTK Query и FSD, и ответы на примерах из «Сальдо».

## Redux Toolkit

**Зачем Redux, если есть Context и useState?**
Context — способ передать значение вниз без пропсов, а не менеджер состояния: при каждом
изменении перерисовываются все потребители. Redux даёт подписку на часть состояния
(`useSelector` перерисует компонент, только если изменился выбранный кусок), DevTools с
историей экшенов, middleware для побочных эффектов. Для темы хватило бы Context, но когда
состояние общее и меняется часто — Redux.

**Что делает createSlice?**
Создаёт редьюсер и экшены из одного объекта. Внутри — Immer: пишем «мутирующий» код,
получаем неизменяемое обновление. Имя экшена — `slice/reducer`.

**Почему в редьюсере нельзя `Date.now()`, `nanoid()`, запись в localStorage?**
Редьюсер — чистая функция: одинаковый вход → одинаковый выход, без побочных эффектов. Иначе
не работают перемотка в DevTools, тесты и предсказуемость. Случайное — в `prepare`, запись —
в listener middleware (тема в «Сальдо»).

**Что такое createEntityAdapter?**
Нормализованное хранение коллекции: `{ ids, entities }` + готовые редьюсеры и селекторы.
В «Сальдо» на нём тосты.

**Зачем createSelector?**
Мемоизация производных данных: пересчёт только при изменении входа, стабильная ссылка на
результат — без лишних перерисовок. В «Сальдо»: строки импорта вычисляются из таблицы и
разметки колонок, а не хранятся.

**Thunk, listener middleware или сага?**
Thunk — разовое асинхронное действие из компонента. Listener — реакция на экшены, сценарии с
ожиданием (`take`, `condition`, `delay`), отмена. Саги — то же, что listener, но с
генераторами и отдельной библиотекой; в новых проектах почти не нужны. Запросы к серверу —
RTK Query.

**Как типизировать store?**
`RootState = ReturnType<typeof store.getState>`, хуки через `useSelector.withTypes<RootState>()`.
В FSD — глобальные типы, чтобы нижние слои не импортировали `app`.

## RTK Query

**Чем RTK Query лучше запросов в useEffect?**
Кеш и дедупликация (два компонента — один запрос), состояния загрузки и ошибки, отмена
устаревших ответов, перезапрос по фокусу и сети, инвалидация после мутаций, оптимистичные
обновления. В `useEffect` всё это пишется руками — и обычно с гонками.

**Как устроены теги?**
Запрос `providesTags`, мутация `invalidatesTags`. Все активные запросы с инвалидированным
тегом перезапрашиваются. `{ type, id: 'LIST' }` — список целиком, `{ type, id }` — запись,
строка без id — всё этого типа.

**Как сделать оптимистичное обновление?**
`onQueryStarted` → `updateQueryData` правит кеш сразу и возвращает патч → `await
queryFulfilled` → при ошибке `patch.undo()`. Найти все места в кеше — `selectInvalidatedBy`.

**isLoading и isFetching?**
`isLoading` — первая загрузка, данных нет. `isFetching` — любой запрос, в том числе фоновый,
когда старые данные уже есть.

**Как сбросить кеш при выходе пользователя?**
`dispatch(api.util.resetApiState())`.

**Почему один createApi на приложение?**
Общий кеш и теги: мутация одной сущности инвалидирует запросы другой. Эндпоинты добавляются
через `injectEndpoints` по сущностям.

**RTK Query или TanStack Query?**
Если уже есть Redux — RTK Query (кеш в DevTools, теги). Если Redux нет — TanStack Query.
Задачу решают одинаково хорошо.

## Feature-Sliced Design

**Какие слои и правило импорта?**
app → pages → widgets → features → entities → shared; импорт только вниз. Слайсы одного слоя
не импортируют друг друга. Наружу — только `index.ts`.

**Чем feature отличается от entity?**
Entity — «что» (операция, счёт: данные и отображение). Feature — «действие с пользой»
(добавить операцию, удалить с отменой, отфильтровать). Кнопка «Удалить» — фича, строка
операции — сущность.

**Что делать, если сущности нужна другая сущность?**
Композиция наверху: виджет собирает строку операции из нескольких сущностей, передавая
пропсы. Если без связи никак — нотация `@x` (публичный API «для конкретного соседа»).

**Куда положить тип RootState / общий API-клиент?**
API-клиент — в `shared/api`, эндпоинты — в сущностях. RootState — глобальный тип из `app`.

**Как проверять, что архитектура соблюдается?**
Steiger (линтер FSD) в CI. Без автоматической проверки границы размываются за пару месяцев.

**Когда FSD — перебор?**
Маленькие и короткоживущие проекты. Правило `insignificant-slice` прямо подсказывает:
слайс, который используется в одном месте, — кандидат на объединение.

## Общие вопросы на примере проекта

**Почему деньги в копейках?** — Плавающая точка: `0.1 + 0.2 ≠ 0.3`. Целые складываются точно.

**Почему фильтры в адресе?** — Ссылкой можно поделиться, работает «Назад», нет второго
источника правды. Адрес → фильтры → запрос.

**Как тестировать код с запросами?** — MSW: тот же код, что в браузере, сервер подменён на
уровне сети. Никаких моков `fetch` и модулей.
