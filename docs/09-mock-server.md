# 09. Демо-сервер

На GitHub Pages нет бэкенда. [Mock Service Worker](https://mswjs.io) регистрирует Service
Worker, который перехватывает `fetch` приложения и отвечает сам. Запросы видны в DevTools →
Network как настоящие, а RTK Query не знает, что сервера нет.

## Устройство

- [seed.ts](../src/shared/mock/seed.ts) — демо-данные: генератор с зерном (одинаковые при
  каждом запуске), 13 месяцев «живых» операций: зарплата 10-го и 25-го, аренда 5-го, продукты
  через день, отпуск в июле, подарки в декабре.
- [db.ts](../src/shared/mock/db.ts) — «база»: фильтры, пагинация, итоги, остатки, проверка
  входных данных. На настоящем бэкенде это был бы SQL и сервисный слой.
- [handlers.ts](../src/shared/mock/handlers.ts) — HTTP: разобрать запрос, вызвать базу,
  вернуть код (200/201/204, 404, 422 с ошибками полей, 503).
- [browser.ts](../src/shared/mock/browser.ts) — запуск в браузере, сохранение в localStorage.
- [node.ts](../src/shared/mock/node.ts) — тот же сервер для тестов (`setupServer` из `msw/node`).

## Отдельный файл в сборке

`main.tsx` загружает MSW динамическим `import()`. С зависимостями это ~150 КБ gzip — больше,
чем всё приложение. Отдельный файл не смешивается с кодом приложения, а с настоящим бэкендом
его просто не загружают.

## Пульт

В консоли браузера:

```js
__saldo.controls.fail = true      // все запросы — 503: экраны ошибок и «Повторить»
__saldo.controls.latency = 2000   // медленная сеть: скелетоны, isFetching
__saldo.controls.latency = null   // «как в жизни» (120–450 мс)
__saldo.db.reset()                // исходные данные (или кнопка «Сбросить демо»)
```

## Настоящий бэкенд

Поменять `API_URL` в [shared/config](../src/shared/config/index.ts) и не вызывать
`startMockServer()`. Контракт — [shared/api/types.ts](../src/shared/api/types.ts).
